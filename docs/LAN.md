# LAN: сопряжение и доверие

LAN v2 использует QUIC поверх UDP и TLS 1.3. Прежний TCP/hash(PIN) протокол
отключён; старые адреса в config сохраняются, но требуют нового сопряжения.

1. Включите LAN в «Подключениях» и сохраните настройки. Разрешите выбранный
   UDP-порт (по умолчанию 47660) в частной сети на обоих устройствах.
2. На принимающем устройстве нажмите «Показать PIN на 2 минуты».
3. На втором найдите первое через «Найти устройства» или введите IPv4/host:port
   вручную. Введите показанный шестизначный PIN и нажмите «Сопрячь».
4. Обновите доверие на обоих устройствах. Сравните шестизначный SAS.
   Подтвердите доверие **на обеих сторонах**, только если SAS совпадает.
5. Синхронизация доступна после обоих подтверждений. Подтверждение на клиенте
   добавляет адрес сервера в его LAN-канал. На сервере входящие запросы
   обслуживаются независимо от списка исходящих адресов.

CLI, при запущенном демоне:

```sh
savesync-daemon remote setup lan 47660 unused
savesync-daemon remote lan invite
savesync-daemon remote lan discover
savesync-daemon remote lan pair 192.168.1.10:47660 123456
savesync-daemon remote lan status
savesync-daemon remote lan confirm <peer_id>
savesync-daemon remote lan forget <peer_id>
savesync-daemon remote lan cancel
```

`unused` — оставшийся для совместимости аргумент старой команды; он не даёт
доступа к сети. Реальный PIN генерируется заново каждым `invite` и хранится
только в памяти. Приглашение действует 120 секунд, допускает пять попыток и
закрывается после первого успешного SPAKE2. Pending trust истекает через пять
минут. Чтобы сопрячь ещё одно устройство, создайте новое приглашение.

mDNS объявляет `_savesync._udp.local.` с версией протокола 2, именем и identity.
Объявления — только подсказки, автоматического доверия нет. Multicast может
блокироваться сетью: используйте ручной IPv4/host. IPv6 пока не используется.
При смене адреса устройства повторите сопряжение по новому адресу и подтвердите SAS.

## Модель безопасности

SPAKE2 формирует одноразовый ключ. Взаимные proof и SAS привязаны к обоим
identity records, обоим PAKE messages и TLS exporter конкретного соединения.
Это предотвращает подмену устройства через relay двух независимых TLS-сессий.
До проверки PAKE и SAS нет доступа к хранилищу. После подтверждения клиент
проверяет pinned certificate сервера; сервер проверяет Ed25519-подпись
клиента над TLS exporter. Replay из другого соединения не проходит. 0-RTT
отключён. Неподтверждённый сертификат разрешён только внутри enrollment.

Identity key и trust store: `<profile>/state/lan-identity/`. На Unix directory
имеет mode 0700, private identity file — 0600; на Windows используется ACL
пользовательского профиля. Не копируйте этот каталог между устройствами.
После потери/замены identity другой участник должен забыть старый ключ и
сопрячь устройство заново. `forget` отзывает доверие локально; повторите на
другой стороне, если удаляете связь полностью.

Сервер ограничивает число одновременных соединений, размеры заголовков и
снапшотов, время handshake/request. Разрешайте входящий трафик только в нужной
локальной сети. Облачные настройки для LAN не требуются.

Тесты используют QUIC по loopback, проверяют обе SAS confirmations, неверный
PIN, отсутствие приглашения, подмену сертификата, replay подписи, отзыв доверия,
перезапуск с сохранённой identity и engine push. Физический роутер и Deck этими
тестами не заменяются.

Справка: [quinn](https://docs.rs/quinn/latest/quinn/),
[SPAKE2](https://docs.rs/spake2/0.4.0/spake2/),
[rustls verification](https://docs.rs/rustls/0.23.45/rustls/client/danger/trait.ServerCertVerifier.html).


Decky QAM содержит те же invitation/PIN/SAS actions через Python-прокси.
Конфликты по-прежнему разрешаются только в desktop app. IPC принимает текущего
владельца профиля; Linux дополнительно допускает привилегированный Decky backend
(root). Клиенты тоже проверяют владельца сервера до отправки PIN/config.
Status остаётся доступным с `busy=true`, пока длительная операция выполняется.
