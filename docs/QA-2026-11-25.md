# QA SaveSync — 25 ноября 2026

Вердикт: **к полному релизу 1.0.0 по HANDOFF пока не готово**.
Завершён аудит исходников независимым QA-агентом; исправлены перечисленные
ниже дефекты. Проверки выполняются без управления компьютером пользователя.
Визуальная проверка GUI и запуск на физическом Steam Deck не заявляются.

## Проверки

- `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`.
- `cargo test --workspace`: регрессии unsafe paths, Windows names, case collisions,
  конфликтов, импорта, нескольких каналов, логических locations, блокировок,
  live LAN config и пересканирования.
- `cargo build --workspace`, `python scripts/smoke.py`: реальные бинарные CLI
  и IPC-запросы в двух изолированных профилях. Ни GUI, ни реальные сейвы не используются.
- Desktop: mock `DaemonClient`, проверка semantic errors и рендер egui
  с `Context` без создания окна.
- Decky: `npm run build` включает `tsc --noEmit`; `npm audit`.
  Python proxy tests требуют Linux AF_UNIX, поэтому локально на Windows
  пропускаются; в Ubuntu CI они обязательны.

## Продолжение: discovery и база

Добавлены проверки вторичной Steam-библиотеки, alias symlink, неоднозначных
Steam IDs, curated fallback с пересечением файлов, восстановления без
локального save directory, запрета пустых snapshots и transactional manifest
update. Windows registry читается без изменений. Тестовые профили задают также
LOCALAPPDATA/XDG_CONFIG_HOME и SAVESYNC_STEAM_ROOT, исключая сканирование
пользовательских игр. Остальные release blockers остаются открытыми.


## Продолжение: транзакционное восстановление

Restore готовит файлы и backups до изменения сейвов. Журнал хранит прежние
index/applied и операции над файлами; per-profile OS lock исключает параллельные
restore/push одного профиля. Неуспешная запись откатывается. Незавершённый журнал
восстанавливается до загрузки Runtime и перед следующей engine-операцией.

Удаляются только имена, присутствовавшие в предыдущем applied snapshot и
отсутствующие в выбранном; новые untracked файлы сохраняются. Если старый архив
недоступен, неизвестные имена не удаляются. Явный rollback создаёт новую merge
версию и не отменяется следующим sync. Совпадение applied ID проверяется по
фактическим размерам и хешам файлов.

Удалённая публикация происходит после локального commit. Если канал недоступен,
сейвы остаются восстановленными; ошибка `RestorePublicationPending` требует
повторного sync и не откатывает уже сохранённое локальное решение.

Проверены fault injection файловой/metadata ошибки, interrupted/committed journal,
удаление stale slot, сохранение untracked, repair текущей версии и retry публикации.
Unix выполняет file+directory fsync barriers. Тесты подтверждают IO failures и
прерывание процесса; физическое отключение питания, аппаратный write cache и
особенности Windows/filesystem durability этими тестами не проверены.


## Продолжение: OAuth

Client IDs настраиваются локально, встроенных приложений нет. Пользователь
подтвердил выбор настраиваемого OAuth. UI открывает системный браузер только
после кнопки входа; CLI печатает URL. Callback слушает только loopback,
проверяет случайный state и S256 PKCE, ограничивает время/размер HTTP-запроса.
Демон не держит Runtime mutex во время ожидания consent/token exchange.

Access/refresh/client secret хранятся отдельными revisions в OS credential
store; config/IPC содержат opaque references. Сохранение новой revision
завершается переключением metadata pointer; ошибка не уничтожает старый token.
Старый plaintext config мигрирует без plaintext fallback. Locked Secret Service
даёт явную ошибку. Отказ облака сохраняет работоспособность остальных каналов.

Автотесты: fake secret store с отказом записи, mock HTTP refresh/rotation,
повтор 401 один раз, отсутствие повтора 403, scope rejection, реальные loopback
callback с неверным/повторным state и PKCE exchange; headless UI polling.
Живой OAuth, OS vault внутри пользовательской сессии и SteamOS Gaming Mode
без разблокированного Secret Service здесь не подтверждены. Подробности:
[OAUTH.md](OAUTH.md).
