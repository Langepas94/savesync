# QA SaveSync — 25 ноября 2026

Вердикт: **к полному релизу 1.0.0 по HANDOFF пока не готово**.
Завершён аудит исходников независимым QA-агентом; исправлены перечисленные
ниже дефекты. Проверки выполняются без управления компьютером пользователя.
Визуальная проверка GUI и запуск на физическом Steam Deck не заявляются.

## Проверки

- `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`.
- `cargo test --workspace`: регрессии unsafe paths, Windows names, case collisions,
  конфликтов, импорта, нескольких каналов, логических locations, блокировок,
  live LAN config и пересканирования.
- `cargo build --workspace`, `python scripts/smoke.py`: реальные бинарные CLI
  и IPC-запросы в двух изолированных профилях. Ни GUI, ни реальные сейвы не используются.
- Desktop: mock `DaemonClient`, проверка semantic errors и рендер egui
  с `Context` без создания окна.
- Decky: `npm run build` включает `tsc --noEmit`; `npm audit`.
  Python proxy tests требуют Linux AF_UNIX, поэтому локально на Windows
  пропускаются; в Ubuntu CI они обязательны.

## Исправления по результатам аудита

| Дефект | Исправление и проверка |
|---|---|
| Выход ZIP paths за save directory | Проверка portable relative paths, device names и symlink ancestors до записи |
| Подмена aggregate hash / размера | Структурная валидация и пересчёт файловых и агрегированного хешей |
| `slot.sav` и `SLOT.sav` / совпадения локаций | Отклонение коллизий до backup и extract |
| `custom:slug` ломает Windows-пути | Единое filesystem encoding; wire key не меняется |
| Второй backend пропускает неизменённый сейв | Кеш и публикация доступной истории перед обновлением индекса |
| Нет кеша у старого состояния | Backfill текущей игры; отсутствие необязательной истории не блокирует latest restore |
| Windows/Proton/Linux пути не сопоставляются | Canonical Proton mapping и явный `location`, сохраняемый в snapshot |
| Все paths пропущены, но Applied выставлен | Неполное сопоставление отклоняется до записи |
| Пустой head паникует, cyclic history зацикливается | Lazy head и ограничение обхода parent-chain |
| Конфликтные головы не видны в history/status | Merged index сохраняется до возврата Conflict |
| Выбор ветки не устраняет конфликт | Новая merge-версия сохраняет старые архивы и объединяет головы |
| Новая версия имеет неверного parent | Используется applied version; resolution ID проверяется на отсутствие коллизии |
| Restore обходит чужую блокировку | Общая проверка foreign lock, включая явную версию |
| Backup копирует соседние игры | Копируются только перезаписываемые файлы; retention после извлечения |
| Кешированный scan теряет новые save slots | Rescan перед sync и backup; regression на glob |
| LAN-конфиг не меняет работающий сервер | Owned listener, проверка bind до сохранения, смена PIN и отключение |
| Ошибка операции показывается GUI как успех | Типизированная проверка результата перед success callback |
| «Обновить» лишь опрашивает статус | Реальный Scan в фоновом job; тест с fake client |
| CLI возвращает 0 при конфликте/ошибке | Ненулевой exit code и проверка реальным smoke script |
| Decky собирается с TS warnings | `tsc --noEmit`, импорт React, корректный icon type и npm lockfile |
| Release job никогда не получает tags | `push.tags: v*`; тег и релиз этим изменением не создаются |

## Реальные блокеры 1.0.0

| Приоритет | Требование | Оставшаяся работа |
|---|---|---|
| P1 | Защищённый LAN из HANDOFF | mDNS, SPAKE2, pinned keys и QUIC/TLS. Текущий TCP с replayable hash(PIN) этим требованиям не соответствует |
| P1 | Конкурентное обновление индекса | CAS/revision или эквивалентная серверная транзакция; read–merge–write может терять ссылки на версии |
| P1 | OAuth и хранение секретов | Browser flow, refresh token lifecycle, OS credential storage; сейчас вводятся access tokens в config |
| P1 | Windows доставка | Установщик, user autostart, tray, обновления и code signing; для реальной подписи нужны сертификат/ключи владельца |
| Закрыт | Поиск игр и база | Runtime discovery appinfo/UFS, Steam-библиотеки на дополнительных дисках, bundled manifests + проверяемый импорт, пустые save directories и запрет пустого upload. Редкие UFS roots/rootoverrides используют curated fallback |
| P2 | Точная семантика восстановления | Удаление устаревших managed files и транзакционный rollback при сбое записи нескольких файлов |
| P2 | Установка на Deck | Проверка настоящего Decky Loader/systemd и реальных save layouts |

Облачные тесты используют mock HTTP servers, а не пользовательские аккаунты.
Исторический архив, уже отсутствующий в источнике, невозможно восстановить из
одного index.json: он не копируется и не рекламируется в новом канале.
Старые snapshots без `location` требуют сохранения исходного pattern в manifest.
Новые snapshots сохраняют логический ID.

Следующий релизный gate: реализовать блокеры, повторить QA и CI на Windows/Linux,
проверить облачный OAuth и физический Deck, затем открыть release/1.0.0 PR.
Текущая ветка — исправления и структурная подготовка, а не подтверждение полной готовности продукта.


## Продолжение: discovery и база

Добавлены проверки вторичной Steam-библиотеки, alias symlink, неоднозначных
Steam IDs, curated fallback с пересечением файлов, восстановления без
локального save directory, запрета пустых snapshots и transactional manifest
update. Windows registry читается без изменений. Тестовые профили задают также
LOCALAPPDATA/XDG_CONFIG_HOME и SAVESYNC_STEAM_ROOT, исключая сканирование
пользовательских игр. Остальные release blockers остаются открытыми.
